# 总管线、断点续跑与成本控制

## 1. 单任务队列

总管线每次只暴露一个 `work/pipeline/next-task.json`：当前缺失章节、当前需修复章节或当前待复盘角色。Agent 只读取该任务声明的输入和规则，不得预先加载后续章节、全部人物档案或整本原文。

章节按 P 编号顺序推进。当前章节分析通过后，先确定性重建角色、人物档案和出镜数据，再为下一章生成包含最新精简角色上下文的工作包。不得一次生成并同时加载所有章节工作包。

## 2. 恢复与失效边界

`scripts/run_pipeline.py resume` 根据输入哈希和各阶段校验器判断状态：

- 原文、章节、当前解析视图和渲染均有效时直接复用。
- 某章分析缺失时只生成该章任务。
- 某章校验失败时只生成该章定向修复包，并列出实际错误。
- 人工验收事件变化时只重建受影响章节及其下游聚合。
- 角色归并或资料确认变化时不回写章节，只重建登记、档案和统计。
- 完整材料仍无法说明的人物参数可验收为保留未知；验收事件绑定当前单角色复盘包指纹，包内容变化后自动重新打开。

`provisional` 章节允许继续流水线；其中的问题继续显示在章节验收清单和制作进度中。结构或证据校验失败才阻止下游。

## 3. 成本信息

状态只统计实际交给下一次 Agent 的单个输入包，不把确定性 Python 重建计作模型调用。保存 UTF-8 字节数和基于字符类别的 Token 粗略区间；由于运行环境可能没有目标模型分词器，区间仅用于发现异常膨胀，实际计费以模型返回值为准。

章节输入、定向修复输入和单角色复盘输入分别计算。若恢复后任务指纹未变，不产生新的语义分析任务；是否再次调用模型由 Agent 在读取队列前判断。

## 4. 用户进度

普通用户读取 `deliverables/制作进度.md`。它只显示章节进度、待确认数量、下一项工作、复用数量和当前输入规模，不展示机器字段路径或事件内容。

机器状态保存在 `data/pipeline/state.json`；全书人物复盘验收记录保存在 `data/pipeline/recap-review.events.jsonl`。两者均由工具维护，用户不直接编辑。

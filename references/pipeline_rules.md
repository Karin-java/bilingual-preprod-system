# V3 轻量调度与恢复规则

## 唯一下一任务

`work/pipeline/next-task.json` 只允许两种语义任务：

- `analyze_chapter`：当前章节尚无结果。
- `repair_chapter`：当前章节结果未通过确定性校验，只修复错误及直接依赖。

Agent 不得另写批量 API 调用脚本、并发提交同一章、提前加载后续章节或要求普通用户配置第三方模型 API。

## 运行顺序

1. `start` 无损接收原稿并生成第一个单章任务。
2. Agent 读取 `next-task.json` 和它指向的单章包，将结果写到声明位置。
3. 运行 `resume`。本地校验、Markdown 渲染和全局目录合并自动完成。
4. 重复第 2–3 步，直到状态为 `ready_for_review`。
5. 用户按编号处理问题和资产范围；再次 `resume`，全部决定完成后状态为 `complete`。

## 成本与恢复

- 一次只处理一个 `PNN`。
- 规则与上下文开销目标不超过 8 KB。
- 章节结构结果不得超过 `源文件 × 4 + 12 KB`。
- 全局操作不调用模型。
- 已通过章节按输入哈希复用；中断、重新开启对话或机器重启后从首个未完成点继续。
- 人工修改只使目标章节和其全局派生视图过期。

## 失败处理

- 校验失败生成小型修复包，错误清单明确可见。
- 修复不得重做其他已通过章节。
- 同一章如果连续无法生成有效结果，保留检查点并向用户报告具体校验错误，不隐藏失败或改走未登记脚本。

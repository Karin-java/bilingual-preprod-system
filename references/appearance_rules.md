# 角色出镜与主要角色场景统计规则

## 1. 数据来源

只读取当前章节解析视图中的 `character_observations`、Scene 信息和统一角色登记表。不得重新读取整本原文、重新推断角色身份或调用模型生成统计。

每条角色观察确定性转换为一条稳定出镜记录：`COBS-P03-0001` 对应 `APP-P03-0001`。角色身份必须通过 `character_key_index` 和旧 ID 重定向解析；不得以显示名称直接分组。主要角色统计读取观察中的角色级 `summary_zh`；旧数据没有该字段时才回退到整场摘要。

## 2. 出现方式

- `physical`：现实画面实际出镜。
- `dream`：梦境画面实际出镜。
- `flashback`：回忆画面实际出镜。
- `mentioned`：仅在台词、叙述或关系说明中被提及，不计为实际出镜。
- `unknown`：材料不足，保持待确认。

`physical`、`dream` 和 `flashback` 均计入出镜场景，但必须保留具体类型。`has_dialogue` 单独统计，不替代出现方式。

## 3. 统一身份与去重

同一角色可能因真名、头衔或旧角色 ID 形成多条观察。机器事实保留各观察的独立 `appearance_id`；用户统计按统一 `character_id + scene_id` 聚合，确保同一角色同一场只显示和计数一次。

尚未达到正式角色登记条件的单次群众候选不进入全角色表，但其观察 ID 保留在机器数据的 `unregistered_observation_ids` 中。群众角色达到有台词或跨位置重复出现条件后，早期观察会自动进入统计。

## 4. 用户交付

- `deliverables/全角色章节出镜表.md`：使用“角色 × 章节”的横向矩阵。第一列为统一角色，后续列严格按 `P01、P02、P03……` 排列；每个角色只占一行，单元格简写该章的现实、梦境、回忆、台词、仅提及或待确认场次。不得渲染成“一个角色一章一行”的纵向明细表。
- `deliverables/主要角色场景统计.md`：每个主要角色使用独立二级标题，标题按“中文名 / 英文名”书写；标题下先写 `**基本信息**`，再用四列表格逐行列出该角色跨章节的 `{P编号章节 + 出场场景（原文位置） + 时间·内外景 + 角色级情节备注}`。不得把多个角色合并到同一张表。基本信息读取人物档案；档案尚未完成时明确写待完整剧本复盘，不得猜测。

主要角色表固定使用以下模板：

```markdown
## 薇奥莱特 / Violette

**基本信息**：狼族公主，战败被俘为国王维克多的奴隶

| 出场章节 | 出场场景（原文位置） | 时间 | 备注 |
|---|---|---|---|
| P12 | 薇奥莱特寝房·窗边 | 日·内 | 窗边闲谈/父往事 |
```

场景地点为 `unknown` 或 `conflict` 时显示“地点待确认”，不得编造泛化场景名。主要角色未完成全书复盘时可以包含 `candidate_major`，但必须明确标记为候选；`**基本信息**` 直接读取 `data/profiles/profiles.json` 的当前摘要，正式定位确认后只需重建派生产物，不回写旧章节。

默认只生成 Markdown。只有用户明确选择某一文件时才单独转换为 DOCX。

# 单章语义结构化规则

## 1. 输入与输出

只读取当前章节的 `work/analysis/pNN.packet.json`，不要加载整本原文。将结果写入工作包声明的 `output_path`，并符合 `schemas/chapter-analysis.schema.json`。

从工作包文件的原始 UTF-8 字节计算 SHA-256，填写 `input_packet_sha256`。原文只能引用，不能改写。

## 2. 文本片段

一个原文单元可包含多个片段。例如同一行中的动作和引号台词必须用字符区间拆开，不能把整行粗略归为一种类型。

- `start` 为片段首字符的零基索引，`end` 为尾字符后一位。
- `source_text` 必须精确等于原文单元的 `[start:end]`。
- 片段不得重叠；所有未覆盖字符只能是空白或换行。
- 片段 ID 按原文顺序使用 `P01-U0001-G001`、`G002` 等。

文本类型：

- `chapter_heading`：章节标题。
- `scene_heading`：原文已有的影视场景标题。
- `action`：画面中可见的动作和行为。
- `narration`：叙述、环境或非直接行动描述。
- `dialogue`：角色实际说出的台词。
- `inner_thought`：未说出口的明确心理活动。
- `voice_over`：旁白、画外音或离屏发言。
- `letter` / `on_screen_text`：信件或画面文字。
- `transition`：明确的转场文字。
- `other`：确实无法归入以上类型的有效正文。

### 标准中文译文

- 在首次逐章语义分析中为每个非空片段同时生成 `translation.text_zh`，不要另开一次全文翻译任务。
- 译文必须完整对应 `source_text`，不得删减信息、补写剧情或擅自修正英文原文。
- 保留原文歧义。例如 `Kings room` 可译为“国王的房间”，不得因当前场景判断而擅自译成“国王卧室”。
- 人名、地名和身份称谓保持章内一致；尚未建立全局术语库时使用当前最佳译名，后续通过稳定片段 ID 统一修订。
- Agent 首次生成使用 `translation.status = agent_draft`；用户针对译文确认后，解析视图使用 `user_confirmed`。
- 剧本、人工验收清单和后续报告必须复用本译文，不得各自重新翻译相同原文。

## 3. 说话人

仅 `dialogue`、`inner_thought` 和 `voice_over` 填写 `speaker`；其他片段必须为 `null`。

- `named`：原文可确认的具名人物。
- `role`：管家、园丁、卫兵等明确身份角色。
- `crowd`：无单体连续性的群体。
- `unknown`：存在发言但无法可靠确认身份。

优先引用同一单元或附近单元中的姓名、动作和发言提示作为证据。不得仅根据台词内容猜测角色。角色库尚未建立时 `character_id` 使用 `null`，保留 `canonical_label` 供后续解析。

## 4. 生产场景

场景是可用于制片的连续时空单元。以下任一项发生明确变化时开始新场景：

1. 物理地点或具体房间改变。
2. 内景与外景改变。
3. 时间发生不连续跳转。
4. 现实、回忆、梦境或想象层级切换。

场景地点使用“归属主体 + 具体空间”，例如“皇宫·东侧走廊”“国王的私人书房”。不要使用“日常卧室”“某处”“室内场景”等无法制片定位的名称。

无法确认地点、时间或内外景时使用 `unknown`，同时将 `review.status` 设为 `provisional` 并登记问题；不要补写原文没有的信息。信息暂缺不等于结构校验失败，允许章节带待确认项进入后续流程。

## 5. 场内 Beat

同一场景中出现以下变化时开始新 Beat，而不是虚构新场景：目标变化、冲突升级、信息揭露、情绪转折、权力关系逆转、关键角色进入或关键行动开始。

场景按原文顺序连续分区；场景内 Beat再次按顺序连续分区。所有有效正文单元必须且只能属于一个场景，也必须且只能属于一个 Beat。章节标题和纯空白单元不进入场景。

## 6. 证据与复核

- `quote` 必须是对应 `source_unit_id` 中实际存在的非空原文子串。
- 明确文字使用 `explicit`；上下文判断使用 `inferred`；矛盾使用 `conflict`；无法判断使用 `unknown`。
- 任何未知说话人、未知地点、未知内外景、未知时间或证据冲突都必须登记在 `review.issues`。
- 待确认项按原文顺序使用稳定 ID：`ISS-P03-0001`、`ISS-P03-0002`。每项必须注明 `scope_type`、`scope_id` 和可选的 `field_path`，使用户能直接定位到章、Scene、Beat、原文单元或片段。
- 只有不存在未解决问题时才能使用 `review.status = ready`。
- 存在待确认项时使用 `review.status = provisional`；只要结构、覆盖和证据合法，校验仍应通过。
- 人工补充或修订不得覆盖本文件。按 `references/review_workflow.md` 追加验收事件并生成解析视图。

## 7. 角色观察

按 `references/entity_rules.md` 在同一次分析中生成 `character_observations`。所有已确认说话人的片段必须被角色观察引用；具名人物、关系角色和群众候选也要保存证据。为每条观察填写简洁的 `summary_zh`，只概括该角色在本场的行动、经历或被提及原因，不要直接复制整场摘要。优先匹配工作包中的精简角色登记上下文，避免跨章重复创建人物。后文真名、头衔或关系称谓与登记角色存在明确身份联系时填写 `matched_character_id`；即使当前 `entity_key` 曾获得其他 ID，也不要隐去该联系，统一登记层会生成待确认归并项。
